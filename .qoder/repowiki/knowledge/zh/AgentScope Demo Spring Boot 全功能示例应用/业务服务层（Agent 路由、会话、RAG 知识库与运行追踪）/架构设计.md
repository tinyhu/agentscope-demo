本模块以 Spring `@Service`/`@Repository` 形式提供横向能力，所有类均位于 `com.skloda.agentscope.service` 包内，依赖方向自上而下：
- 编排层 `AgentService`：统一入口，根据 `AgentType`（SINGLE/HARNESS/ROUTING）分流到 `HarnessAgentService`、`SupervisorRuntimeFactory` 或底层 `StreamingAgentRuntime`，并通过 `SessionManagerService`、`WorkflowRunService`、`ChatHistoryRepository` 完成会话、工作流记录和聊天历史写入。
- 会话层 `SessionManagerService`：维护 `ConcurrentHashMap` 形式的 `SessionContext`（含 `ReActAgent`、`AgentStateStore`、`lastAccessedAt`），支持按 `agentId` 创建/查找/迁移/删除会话，并通过 `AgentFactory` 构造持久化或内存态 state store。
- 审批中间件协调 `ApprovalService`：基于 `ConcurrentHashMap<String, PendingApproval>` 缓存暂停的 ReActAgent，并由 `@Scheduled(fixedRate = 60000)` 定期清理过期条目。
- RAG 知识库 `KnowledgeService` + `KnowledgeProperties`：启动时通过 `ApplicationReadyEvent` 触发单线程 `ExecutorService` 异步扫描本地目录并使用 `SimpleKnowledge`(DashScopeTextEmbedding + InMemoryStore) 进行文档分块索引；对外暴露 `addDocument`、`getIndexStatus` 及受 `agentscope.knowledge.*` 配置开关的能力。
- 持久边界 `ChatHistoryRepository` + `InMemoryChatHistoryRepository`：定义按 agentId 增删查 chat transcript 的接口，当前仅内存实现，便于替换为 Redis/JDBC。
- 运行追踪 `WorkflowRunService`：在 `ConcurrentHashMap<String, MutableWorkflowRun>` 中记录每次 agent run 的输入预览、事件序列和状态（RUNNING/COMPLETED/FAILED），并以固定容量裁剪历史。
测试覆盖对应服务的核心路径（会话存活、RAG 索引状态、工作流运行列表、审批过期清理）。
