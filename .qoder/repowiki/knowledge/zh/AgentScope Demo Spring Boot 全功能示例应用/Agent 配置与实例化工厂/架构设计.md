模块采用“配置模型 + 加载器 + 工厂”三层结构：
- 配置模型层：`AgentConfig` 为核心 POJO（含嵌套 `HarnessConfig`、`SharedBlackboardConfig`、`RoutingConfig`、`PermissionConfig`、`SessionConfig`、`LongTermMemoryConfig` 等），配合 `AgentType` 枚举（SINGLE/SEQUENTIAL/PARALLEL/ROUTING/HANDOFFS/LOOP/STATE_GRAPH/MSG_HUB/SUBAGENT_SEQ/SUBAGENT_PAR/HARNESS）描述智能体类型；`LoopConfig`、`StateConfig`、`StateTransition`、`SubAgentConfig`、`HandoffTrigger`+`TriggerType`、`MsgHubConfig`、`SamplePrompt` 提供各高级模式的细粒度配置。
- 配置加载层：`AgentConfigService` 通过 Spring `@Value` 注入 `agents.yml` 与 `harness-agents.yml`，使用 SnakeYAML + `AgentsWrapper` 批量反序列化进内存 Map，并维护去重、排序列表，同时从 `ToolRegistry` 抓取 skill/tool 元数据暴露查询 API（`getSkillInfo`、`getToolInfo`）。
- 工厂层：`AgentFactory` 作为 Spring @Service，依赖 `ModelFactory`、`ToolRegistry`、`MiddlewareRegistry`、`McpClientService`、`KnowledgeService`、`PermissionContextFactory`，根据 `AgentConfig` 装配 ReActAgent 或 HarnessAgent，支持状态存储选择（InMemory / JsonFile / 可选分布式 AgentStateStore）、PlanNotebook、RAG（v1 已标记废弃）、长短期记忆、MCP 工具、中间件链与审批式 HITL 中间件注入。
- 依赖方向单向：AgentConfigService → ToolRegistry；AgentFactory → ModelFactory/MiddlewareRegistry/McpClientService/KnowledgeService/PermissionContextFactory；配置类本身无外部依赖，仅被 Service/Factory 消费。
- 测试层通过单元测试分别覆盖所有配置 DTO 与枚举的默认值、边界与匹配逻辑（如 HandoffTrigger.matches）。
