模块以 `HarnessAgentService`（Spring @Service）作为对外入口：接收 `agentId + executionMode`，按 `agentId:MODE` 组合键在 `ConcurrentHashMap` 中缓存 `HarnessAgent` 实例，并通过注入的 `RuntimeContext.sessionId/userId` 调用 `HarnessRuntime.stream()` 返回 SSE 兼容的 `Flux<Map<String,Object>>`。
- 装配层 `HarnessAgentFactory`（@Component）是核心装配点：读取 `AgentConfig`/`HarnessConfig`，通过 `ModelFactory` 解析模型，依据 `dockerMode` / `isBuilder` 选择 `FilesystemSpecFactory` 产出的 Docker 或 Local 文件系统，再依次装配 compaction、tool result eviction、Task List、Plan Mode、Layered Memory、Permission Context、Skill Repository、additional context、meta tool、skill self-learning 等能力，最终构建 `HarnessAgent.Builder`。
- 执行层 `HarnessRuntime` 实现 `StreamingAgentRuntime`，统一复用 `AgentEventMapper` 把 AgentScope 2.0 的 `agent.streamEvents()` 转换为前端统一的 Map 流，并以硬编码 `{type: done}` 收尾；同时挂载 `ObservabilityHook` 用于可观测性。
- 依赖注入对象集中解耦：`FilesystemSpecFactory` 封装 Local/Docker 沙箱默认参数（镜像、内存、CPU、环境变量），`CompactionConfigFactory` 统一产出 `CompactionConfig` 与 `ToolResultEvictionConfig`，`WorkspaceInitializer` 负责从 classpath `harness-templates/<agentName>/...` 资源幂等复制到 sandbox/workspace 目录，`UploadsArtifactDeliveryTarget` 实现 agentscope 2.0.3 的 `ArtifactDeliveryTarget` SPI 将产物写回宿主机 tmpdir。
- 模块仅通过 `AgentConfig`/`AgentConfigService`/`ModelFactory`/`PermissionContextFactory` 等接口与外部交互，不直接持有 Spring 容器。
