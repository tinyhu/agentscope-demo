模块以 `io.agistscope.core.middleware.MiddlewareBase` 为统一扩展点，每个类覆写 `onAgent/onReasoning/onActing/onModelCall/onSystemPrompt` 等方法在事件流链中截获并转换数据；未覆盖的方法默认透传至 `next.apply(input)`。`MiddlewareRegistry` 是唯一的装配中心：使用 `LinkedHashMap<String, Supplier<MiddlewareBase>>` 维护名称到构造器的映射，通过 `@PostConstruct registerBuiltInMiddlewares()` 自动登记 audit-logging、rate-limit、context-enrichment、detailed-audit、metrics-collector，以及桥接的 otel-tracing 和 final-answer-filter；外部通过 `create(name)` 按 kebab-case 名称工厂式创建实例。各中间件职责单一且无相互依赖：`AuditLoggingMiddleware`/`DetailedAuditMiddleware` 记录事件与耗时；`RateLimitMiddleware` 用 `LinkedList<Long>` 实现 60s 滑动窗口限流；`ApprovalMiddleware` 在 `onActing` 阶段检测需审批的工具调用并返回 `Flux.empty()` 阻断执行；`MetricsCollectorMiddleware` 通过 `ThreadLocal<MetricsContext>` + 全局 `ConcurrentHashMap`/`AtomicLong` 聚合性能与成本指标；`ContextEnrichmentMiddleware` 在 `onSystemPrompt` 注入时间戳与用户身份。所有中间件均为独立类（除 `MiddlewareRegistry` 标记 `@Component`），由上层运行时按顺序组装成 Reactor `Flux` 管道。
