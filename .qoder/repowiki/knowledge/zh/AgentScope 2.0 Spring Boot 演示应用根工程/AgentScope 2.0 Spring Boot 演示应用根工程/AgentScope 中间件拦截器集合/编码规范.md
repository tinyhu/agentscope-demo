- 每个中间件实现 `io.agentscope.core.middleware.MiddlewareBase` 并通过覆写生命周期方法拦截事件流，未覆盖的方法直接调用 `next.apply(input)` 透传上游链路。
- 对上游链路的回调统一通过 `return next.apply(input)` 委托，并在 Reactor 链路中使用 `doOnComplete/doOnError` 钩子统计耗时或记录错误。
- 中间件以独立类组织单一关注点，状态存储采用线程安全结构（如 `RateLimitMiddleware` 的 `LinkedList<Long>`、`MetricsCollectorMiddleware` 的 `ConcurrentHashMap`/`AtomicLong`、`ThreadLocal<MetricsContext>`）。
- 日志输出使用 SLF4J `LoggerFactory.getLogger(...)`，并以带前缀的 `[audit]/[rate-limit]/[METRICS-COLLECTOR]` 等标识便于过滤区分。
- 通过 `MiddlewareRegistry` 的 `register(name, Supplier<…>)` 工厂模式注册中间件，再以 kebab-case 字符串名供上层按名称查找创建。
- 单元测试采用 JUnit 5，构造空的 `RuntimeContext.empty()` 和模拟 `Flux.just(fakeEvent)` 注入下游，用 `.collectList().block()` 断言事件数量与内容。
