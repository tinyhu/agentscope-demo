模块围绕“单一写手 + 只读快照 + 不可变补丁”协议组织：
- 入口 `SupervisorRuntime` 实现 `StreamingAgentRuntime`，每轮 `stream()` 在 `(userId,sessionId)` 粒度加 `ReentrantLock`，读取 `BlackboardService` 提供的防御性 `SessionBlackboard` 快照后进入决策阶段。
- `RoutingDecisionService` 按 `AgentConfig.RoutingConfig.strategy`（rule/llm）输出 `RoutingAction {KEEP,SWITCH,CLARIFY,MULTI}` 与 selectedExpert、reason、confidence；默认 rule 策略用显式/意图触发器的关键词匹配并优先 SWITCH > KEEP > CLARIFY。
- `ExpertAgentProvider` 每次分发构建全新 `ReActAgent`，使用独立的 `InMemoryAgentStateStore` + 以 `<sessionId>::<expertId>` 命名的 expert 域 session，保证专家私有态互不泄漏。
- 持久层由 `BlackboardService` 统一封装，基于可插拔 `AgentStateStore`（默认 InMemory，生产注入 Redis/MySQL/Postgres profile），所有读写走 per-slot 锁，版本单调递增。
- 数据契约分层：`SessionBlackboard`（聚合 facts/slots/businessState/findings/unresolvedQuestions 的 State 实体）、`BlackboardPatch`（仅允许修改的不可变增量）、`ExpertRequest/ExpertResult/ExpertFinding`（专家间通信消息）。`SupervisorRuntimeFactory` 装配这些组件。
- 事件流层面，Supervisor 向下游 emit `routing_event`、转发专家事件但过滤掉 `text/agent_start/agent_end/agent_result_text` 避免前端重复渲染，最终返回 standard `done`。
