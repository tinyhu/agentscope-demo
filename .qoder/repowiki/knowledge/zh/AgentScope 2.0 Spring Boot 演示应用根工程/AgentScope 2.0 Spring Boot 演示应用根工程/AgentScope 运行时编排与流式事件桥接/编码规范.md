- 每个运行时实现 `StreamingAgentRuntime` 并在 `stream()` 中将 `hook.getEventSink().asFlux()` 与编排产生的 `Flux` 通过 `Flux.merge` 合并，确保手动事件与子代理事件在同一 SSE 通道中流转。
- 流结束与资源清理通过 `doOnCancel(this::close)`、`doFinally(s -> close())` 或 `doOnComplete(this::close)` 配合 `hook.getEventSink().complete()` 完成，避免 Sinks 悬挂导致前端永久保持 streaming 状态。
- 事件内容统一封装为 `Map.of(...)` 或 `LinkedHashMap`，并通过固定 `type` 字段区分事件种类（如 `pipeline_step_result`、`task_result`、`text`、`done`、`error`、`pending_approval`）。
- 子代理执行统一调用 `MultiAgentStreamSupport.runSubAgent(agent, msg, agent.getName(), fluxSink, onError)` 来获取带 source 标签的 SSE 转发和最终文本返回值，避免直接 copy 粘贴 streamEvents 转发逻辑。
- 编排管道使用 `hook.emitPipelineStart` / `emitPipelineStepStart` / `emitPipelineStepEnd` / `emitPipelineEnd` 四件套标记步骤起止与耗时，并在成功时追加 `pipeline_step_result` 聚合输出。
- 调试输出的大段内容通过私有 `truncate(String, int)` 方法裁剪（常见上限 500 字符），避免过长 SSE payload 污染日志与前端显示。
