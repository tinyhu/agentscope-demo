模块以 `StreamingAgentRuntime` 接口为统一契约，所有运行时实现均暴露 `stream(Msg) -> Flux<Map<String,Object>>`，由 `AgentRuntimeFactory` 根据 `AgentConfig.type`（SINGLE/ROUTING/HANDOFFS/STATE_GRAPH/MSG_HUB/HARNESS/SEQUENTIAL/PARALLEL/DEBATE/LOOP/SUBAGENT_SEQ/SUBAGENT_PAR）分发创建对应运行时。

核心分层：
- 单一代理层：`AgentRuntime` 通过 `agent.streamEvents()` + `AgentEventMapper` 将 AgentScope 原生事件转为 SSE payload，并合并 `ObservabilityHook.getEventSink()` 中的手动事件；支持 HITL 审批中断后的 resume（approvalMiddleware 检查 pending tool calls）与 MCP 来源溯源注入。
- 结构化输出层：`StructuredOutputAgentRuntime` 走 `agent.call(msg, Class)` 阻塞路径，经 `StructuredOutputValidator` 校验并自动修复重试，再产出 `structured_data` 事件。
- 多代理编排层：`SequentialRuntime`/`ParallelRuntime`/`DebateRuntime`/`LoopRuntime`/`MsgHubRuntime`/`SubAgentSeqRuntime`/`SubAgentParRuntime`/`StateGraphRuntime` 复用 `MultiAgentStreamSupport.runSubAgent` 将每个子代理的 `AgentEvent` 转发到共享 `FluxSink`，并以带 source 标签的 Map 标注来源；编排结果用 `pipeline_start/step_start/end/end` 事件包裹时序元数据。
- 基础设施：`EventSink` 基于 `Sinks.Many.multicast().onBackpressureBuffer()` 作为轻量事件总线，集中声明 pipeline/handoff/routing/loop/graph/roundtable/task 等事件类型常量及便捷 emit 方法；`ObservabilityHook` 在外部持有该 sink，供各运行时发布可观测事件。
依赖方向单向：运行时 → ObservabilityHook / MultiAgentStreamSupport / AgentEventMapper / ApprovalMiddleware → EventSink，无反向依赖。
